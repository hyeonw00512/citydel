# 왕관의 도시 — Phase 1~20

시타델 스타일의 실시간 멀티플레이 웹 보드게임 MVP입니다. 자체 제작한 설명 문구와 UI를 사용하며, React/Vite 클라이언트와 Express/Socket.IO 서버가 npm workspace로 구성되어 있습니다.

## 구현 범위

- 2~8명 방 생성, 6자리 방 코드, 초대 URL, 참가, 준비, 방장 시작
- 로비에서 방장이 선택하는 기본·마녀~외교관·치안판사~육군대장 권장 직업 세트와 세트별 연동 9번 직업
- 방장이 켜고 끌 수 있는 9번 직업 모드와 권장 조합 복귀·여왕·예술가·세금징수관 커스텀 선택
- 서버 authoritative 게임 상태와 Phase 검증
- 순차 비밀 역할 선택 및 역할 rank 기반 턴 진행
- 공개 상태 / 개인 상태 / 서버 전용 상태 분리
- `playerToken`과 `roomCode` 기반 새로고침·일시 연결 끊김 복구
- 현재 순서의 연결 끊김 플레이어는 30초 뒤 역할 자동 선택·금화 수입·능력 건너뛰기·턴 종료로 안전하게 진행
- PC·모바일 반응형 UI와 safe-area 대응
- 역할 정의를 `server/src/game/roles/roles.ts`에서 데이터로 관리
- 게임 시작 시 금화 2개와 건물 손패 4장 지급
- 턴별 금화 수입 또는 카드 2장 중 1장 선택
- 서버의 손패·금화·중복 검증을 거치는 건물 건설과 공개 도시 상태
- `ACTION` 단계의 데이터 기반 역할 능력과 턴당 1회 사용 검증
- 암살자·도둑의 비밀 역할 지정(행동 봉쇄·금화 탈취)과 서버 전용 효과 처리
- 마술사의 서버 검증 손패 교환 및 다시 뽑기
- 세금징수관의 서버 전용 수동 건설 세금 수입
- 장군의 군사 수입 및 서버 검증 건물 파괴
- 학자의 비공개 설계도 5장 연구 및 1장 선택
- 예술가의 도시 건물 장식과 최종 점수 +2 반영
- 밀정의 도시 색상 정찰과 대상 플레이어 수만큼의 설계도 획득
- 예언자의 서버 검증 타 플레이어 두 명의 비공개 손패 교환
- 마법사의 서버 무작위 타 플레이어 설계도 1장 획득
- 치안판사의 비공개 위협 표식과 대상의 다음 건설 추가 비용 1개
- 입장 순서 기반 원형 좌석과 여왕의 4번 역할 인접 금화 3개 보상
- 마녀의 비공개 역할 지정과 대상 차례의 자원·손패 기반 턴 위임
- 효과 건물: 별빛 관측소의 3장 카드 수입, 대장간의 카드 제작, 연구소의 카드 환전, 성채의 파괴 방지
- 효과 건물 확장: 대도서관의 3장 중 2장 카드 수입, 묘지의 20초 파괴 건물 회수, 성벽의 장군 파괴 비용 +1, 마법 학교의 선택 색상 수입, 지도실의 손패 점수, 황제의 보물고의 금화 점수, 유령 도시의 색상 완성 보정, 대학·용의 관문의 최종 점수 +2
- 참가자 검증, 길이 제한, 최근 100개 보관을 적용한 실시간 방 채팅
- 섭정·수도원장·교역상·원수의 건물 색상별 추가 수입
- 건축가의 카드 2장 획득과 최대 3회 건설
- 숨겨진 정보를 제외하고 최근 50개를 보관하는 공개 게임 로그
- 원작 수정판 기준 인원별 도시 완성(2~3인 8채, 4~8인 7채) 감지와 현재 라운드 종료 후 게임 종료
- 원작 수정판 기준 2~3인 게임의 플레이어당 역할 2장 선택 및 역할 순위별 개별 턴 진행
- 원작 수정판 기준 3·8인 9번 직업 필수, 4~7인 선택 및 3·4인 여왕 제외 규칙의 서버 검증
- 왕 역할의 실제 턴 시작 시 왕관 이동 및 왕관 보유자부터 시작하는 다음 라운드 역할 선택
- 인원·9번 직업 구성에 따른 역할 카드 공개·비공개 제외와 4번 역할 공개 제외 방지
- 7·8인 게임 마지막 선택자의 초기 비공개 제외 역할 포함 2장 선택 특수 규칙
- 2인 게임 두 번째 역할 선택 뒤 개인별 비공개 역할 제외 단계와 연결 끊김 자동 처리
- 3인 게임 세 번째 플레이어의 첫 역할 선택 뒤 중간 비공개 역할 제외 단계
- 장군의 완성 도시 파괴 금지 및 자기 도시 건물 파괴 허용 서버 규칙
- 게임 종료 후 방장이 같은 멤버·방 설정으로 시작하는 재대결
- 건물 비용·5색 완성·도시 완성 순서를 반영한 서버 점수 계산과 최종 순위

직업 세트의 명칭과 rank 구성은 게임 흐름 검증을 위한 데이터로만 사용하며, 설명 문구와 화면 디자인은 프로젝트용으로 새로 작성했습니다. 아직 활성화되지 않은 대상 지정 능력은 UI에서 명확히 표시됩니다.

마녀·치안판사 등 변형 세트의 대상 지정 능력은 아직 포함하지 않습니다. 서버는 메모리 기반이므로 서버 프로세스를 재시작하면 방이 초기화됩니다.

## 설치 및 실행

Node.js 20 이상을 권장합니다.

```bash
npm install
npm run dev
```

Codex 내장 Node.js 환경을 사용하는 경우에는 의존성 설치 후 다음 명령으로 바로 실행할 수 있습니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\start-dev.ps1
```

- 게임 화면: `http://localhost:5173`
- 서버 상태: `http://localhost:3001/health`

빌드와 자동 테스트:

```bash
npm run typecheck
npm test
npm run build
```

## 같은 Wi-Fi의 모바일/LAN 테스트

1. Windows 터미널에서 `ipconfig`로 PC의 IPv4 주소를 확인합니다(예: `192.168.0.10`).
2. 개발 서버를 `npm run dev`로 실행합니다. Vite와 게임 서버 모두 이미 `0.0.0.0`에서 수신하도록 설정되어 있습니다.
3. Windows 방화벽이 묻는 경우 Node.js의 개인 네트워크 접근을 허용합니다.
4. 같은 Wi-Fi에 연결된 모바일 Chrome/Safari에서 `http://192.168.0.10:5173`을 엽니다.
5. PC에서 방을 만들고 모바일에서 초대 URL을 열거나 방 코드를 입력합니다.

서로 다른 외부 네트워크에서 플레이하려면 클라이언트와 서버를 HTTPS 지원 호스팅에 배포하고 `VITE_SERVER_URL`을 공개 서버 주소로 지정해야 합니다. Socket.IO 서버의 `CLIENT_ORIGIN`도 실제 클라이언트 주소로 설정할 수 있습니다.

## Render 배포

저장소 루트의 `render.yaml`은 클라이언트 빌드 결과와 Socket.IO 서버를 하나의 Render 웹 서비스로 배포합니다. Render에서 **New → Blueprint**를 선택해 GitHub 저장소를 연결하고 배포하면 됩니다. 배포 뒤 표시되는 `https://...onrender.com` 주소가 게임 접속 주소입니다.

Render 무료 인스턴스는 유휴 상태에서 잠들 수 있으며, 이 게임의 방 정보는 서버 메모리에만 보관됩니다. 따라서 서버가 재시작되면 진행 중인 방은 초기화됩니다.

## 수동 멀티플레이 확인

1. 일반 창과 시크릿 창(또는 PC와 모바일)에서 각각 다른 닉네임으로 접속합니다.
2. 한쪽에서 방 생성 후 다른 쪽에서 코드로 참가합니다.
3. 방장이 직업 세트를 바꾸고 모든 참가자의 로비에 동일하게 표시되는지 확인합니다.
4. 9번 직업 모드를 켜고 여왕·예술가·세금징수관 중 하나를 선택합니다.
5. 모두 준비하고 방장이 시작합니다.
6. 2~3인 게임에서는 각 플레이어가 역할을 두 번 선택하고, 내 화면에서만 두 역할이 함께 보이는지 확인합니다.
7. 역할 선택 완료 후 모든 선택 역할이 낮은 rank부터 각각 한 번씩 턴을 받는지 확인합니다.
8. 한 화면을 새로고침해 같은 플레이어로 복구되는지 확인합니다.
9. 개발자 도구의 `room:state` 패킷에 플레이어별 선택 역할 ID가 없는지 확인합니다.

## 구조

```text
client/  React + TypeScript + Vite UI
server/  Express + Socket.IO + 게임/방/턴/역할 계층
shared/  클라이언트/서버 공통 이벤트와 상태 타입
```
